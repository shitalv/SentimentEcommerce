MongoDB Error Handling and Sample Data Removal

Changes made:

1. Removed all sample data fallback mechanisms from mongo_config.py
   - Modified get_db() to throw exceptions instead of silently returning mock data
   - Updated setup_db() to raise clear errors instead of falling back to sample data
   - Fixed get_mongo_client() to properly raise exceptions

2. Updated time_based_analysis_api.py with proper MongoDB connection handling
   - Added explicit error checking after MongoDB client connection
   - Ensured all unpacked client/db variables are properly assigned
   - Added checks to confirm DB connection before performing queries

3. Improved error visibility and transparency
   - Added more detailed error messages when MongoDB connection fails
   - Removed silent fallbacks to ensure users know when data is unavailable
   - Enhanced logging to show MongoDB query parameters

These changes ensure the application only uses real MongoDB data and never silently
falls back to sample data. If MongoDB connection fails, clear error messages will
be displayed to the user instead of fake data being shown.
